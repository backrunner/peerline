## Transfer performance

Peerline now builds one archive per send and shares it across retries and candidate routes. Each active route can prefetch up to 512 KiB while sending. The receiver can fill one 1 MiB buffer while writing another, then waits for disk I/O when both are full.

In a macOS loopback TCP test with simulated slow disk I/O on both ends, sending a 64 MiB file took 6.58 seconds end to end, down from 23.54 seconds in beta.2. These are medians of three runs, including packing, verification and extraction. Median peak RSS increased from 32.2 to 32.9 MiB on the sender and from 62.5 to 64.3 MiB on the receiver.

## Resuming a transfer

Restart the receiver in the same destination directory, then resend the same paths with the same compression setting from the original sender. The receiver saves a checkpoint after the first chunk, after another 8 MiB or on the next chunk after five seconds, and at the end. A retry discards any uncommitted tail and verifies the complete archive before extraction.

Beta.3 uses transfer protocol v4 and can resume archives created by beta.2. Recovery was verified by killing the receiver process, restarting both CLIs and checking the resumed offset and final file hash. Extraction still publishes files individually. If extraction is interrupted, files already published can receive numbered copies on retry with the default overwrite settings.
